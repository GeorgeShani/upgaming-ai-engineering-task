# Slice 8: reproduce and understand the comparison

Read `evaluation-methodology.md` for the predeclared definitions, selection rule, denominators
and limits. `evaluation-reference-caveats.md` records ambiguous source/reference cases identified
before final model runs. The measured results and raw receipts are linked in the final report.

## 1. Understand what changes

Only chunking strategy A/B changes. Both use the same source corpus, embedding dimensions/model,
generation snapshot, prompts, retrieval sizes, RRF algorithm and eight-chunk final context.
The agent's actual search wording can vary, because it is generated by a model. Alternating
which configuration runs first reduces order bias; it does not make the model deterministic.
One A/B trial per question is a descriptive comparison, not a causal statistical proof.

Gold labels live only in offline scoring. Investigation receives `{question, strategy}` and
retrieved source text. It never receives the reference answer or required-document IDs.
The corpus deliberately includes the supporting source passages; this measures retrieval and
grounded answering given available evidence rather than independent corpus coverage.

## 2. Inspect the free preflight

Keep other paid app/indexing work idle. From the repository root:

```powershell
uv sync --frozen --group data
uv run python -m backend.app.evaluation_cli preflight
```

This validates the pinned prepared corpus/fixture hashes, verifies active cloud manifests
against every source ID/hash/index profile and counts physical points. It computes expected
active chunk counts and how often the strategies have identical spans. It makes read-only
Qdrant requests and no model calls. It writes `artifacts/evaluation/manifest.json` and the cost
projection. Models/rates, code hashes, package versions, collection profile and corpus identity
are recorded without credentials or private cluster URLs.

If `data/prepared` is missing, use the dataset preparation instructions in README first.
Do not reindex or change the corpus during a comparison. Existing physical points include
inactive revisions, which retrieval filters out; they are not extra canonical documents.

## 3. Run development, select, then run final

These `run` commands make paid calls. The existing local ceiling is $4.50 within the $5 target.
The original completed run is already saved; you do not need another paid run to understand it.

```powershell
uv run python -m backend.app.evaluation_cli run --split development
uv run python -m backend.app.evaluation_cli summarize --split development
uv run python -m backend.app.evaluation_cli select
# Inspect selection.json before the final command.
uv run python -m backend.app.evaluation_cli run --split final
uv run python -m backend.app.evaluation_cli summarize --split final
```

The local command calls the production bounded service directly and serially. The website's
six-per-minute HTTP admission limit remains unchanged. There are 8×2 development attempts and
40×2 final attempts. Per-attempt receipts are saved atomically. A failed model/storage request
stays in the denominator, retains its usage/reservation and stops the command for inspection.
After reviewing it, repeat `run` with the same split/output to continue only absent attempts.
Completed failures are never silently retried. Interrupted pending attempts are marked uncertain,
not replayed. An exclusive output lock is released automatically if the process exits.

Resume rejects changed code/settings/corpus/fixtures. Final execution requires a previously
frozen development selection, and validates that its development receipts have not changed.
Corpus identity is checked again at each phase end. These checks can take longer than a question;
they are read-only and do not incur model cost. A new study needs a new `--output` directory,
an explicitly versioned configuration and a fresh final set if you intend to tune further.

## 4. Read a receipt and calculate a metric

Pick `final-bridge-01-a.json` (or a development case first). Follow the question through
`result.search_trace`, the observed query, ranked document IDs, retrieved text and evidence IDs.
Then inspect `result.evidence`, claims/citations and `result.usage`. Ledger before/after also
records known usage and reservations from failed calls. `scores.json` contains offline judgments;
`summary.json` aggregates them with explicit sample sizes.

For two required sources, ranks 1 and 12 give Recall@5=0.5 and MRR@10=1.0. The first source was
found immediately, but the chain is incomplete. Compare `all_sources_retrieved`,
`all_sources_in_context` and `all_sources_cited` to see where a second source was lost.
The all-search ranking is a diagnostic document-level RRF across executed searches, separate
from the production final-context selection. Repeated/cached identical searches are not extra
independent evidence. The primary initial-search scores isolate that first retrieval step.

Exact match compares normalized generated prose to the frozen short reference. The last-claim
score follows the prompt's convention of placing the requested fact last; it never extracts a
substring using gold text. This can penalize a useful explanation. Expected-fact coverage helps
expose that issue but cannot detect negation or incorrect entity binding. Inspect the answer.

Citation validity asks whether the quote exists in a known retrieved chunk at matching canonical
offsets. Labelled citation precision adds gold-source/quote alignment. Neither proves the claim
follows from that quote. Inspect the actual date, entity, negation, units and conflict scope.
The review notes name Codex as the reviewer; they do not impersonate your independent work.

## 5. Verify without another paid run

Run backend tests and offline summaries. For the exact archived study, use its saved raw
receipts and the same committed scorer/input hashes; do not re-run model calls to get a better
score. A new model run is stochastic and may differ even with the same snapshot.

```powershell
uv run --group data pytest -W error
uv run ruff check backend
uv run ruff format --check backend
uv run python scripts/verify_evaluation_archive.py
```

Archive contents: root manifest/cost projection/selection; development and final run/checkpoint
files; one raw JSON per attempt; scored rows and summary; qualitative review. The full corpus
stays under ignored `data/`; hashes and preparation commands reproduce it. Outputs contain
public benchmark and fictional evidence, with no keys or original private uploads.
